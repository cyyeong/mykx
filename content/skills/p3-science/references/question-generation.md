# Generating questions and papers

---

## 2. Synthesis recipe — new questions, not copies

Keep the **skill**, change the **surface**:
- swap the organism/material/object (grasshopper → cockroach; tent → umbrella);
- swap letters, numbers and which column is missing;
- invert the question ("which is suitable" → "why is X *not* suitable");
- change the representation (table ↔ bar graph ↔ diagram ↔ flowchart);
- add one step for difficulty (pole chain of 4 magnets instead of 2; "after
  hatching" instead of "total");
- combine two sub-skills only once the single skills are secure (fair test +
  material choice).

Difficulty levels (store as `difficulty` 1–5): 1 recall · 2 one-step apply ·
3 read data + apply · 4 two-step reasoning or trap · 5 unfamiliar context + CER.
A diagnostic uses 2–3; drilling a weak sub-skill climbs 1 → 4; mocks mirror the
school paper (mostly 2–4 with a few 5s).

## 3. Quality checklist (do every time — a wrong key teaches the wrong science)

- [ ] Inside the seven sub-topics and the depth limits (`syllabus-map.md`).
- [ ] **Exactly one** correct MCQ option. Work every option out explicitly.
      Remember cyclic rotations of a life cycle are the *same* cycle.
- [ ] Answer positions balanced across (1)–(4) — never let one number dominate.
- [ ] Distractors are *plausible* and each maps to a real misconception (write it
      in `distractors`).
- [ ] Every figure label in the stem matches the figure (letters, units, N/S).
- [ ] Numbers in tables/graphs give the intended answer (re-add the bars).
- [ ] OEQ model answers are CER, with the keyword in **bold**, plus accept/reject.
- [ ] Tags are valid (`skill.json`); every Booklet B part has a `subskill`.
- [ ] Language: short sentences, P3 vocabulary, Singapore context, kid-safe.
- [ ] Rendered and looked at. Nothing overlapping, nothing cut off.
